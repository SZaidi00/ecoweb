# Phase 5 — Browse layer + content expansion

## Objective
Complete the zoom hierarchy: biome landing page → ecosystem index → web view, with breadcrumbs throughout. Add 3–5 more curated ecosystems so the product feels like an atlas, not a demo.

## Read first
`plan/00-MASTER-PROMPT.md` + this file.

## Tasks

1. **Landing page (`#/`)** — the product's identity:
   - Hero line + short pitch ("Every species depends on something. See it.").
   - Biome grid (marine, freshwater, terrestrial-forest, grassland, tundra, wetland…). Biomes with content are rich cards; empty ones show a tasteful "Coming soon" state (never fake content).
   - Biome → ecosystem cards: name, location, node count, provenance badge (Empirical study / Curated composite), one-line hook ("Home to one of the best-studied keystone cascades").
2. **Routing & breadcrumbs:** `#/` → `#/biome/:biomeId` → `#/web/:webId` → focus state reflected in breadcrumb text ("Marine › Prince William Sound › Salmon"). Back button works at every level (hash history).
3. **New ecosystems (3–5):** prioritize data strength and variety. Suggested set: Chesapeake Bay (estuarine), a freshwater lake web, a wetland web, one terrestrial web — **only where real published data is verifiable via Web of Life / GloBI / primary literature.** Each goes through the Phase 1 pipeline: schema validation, real or qualitative-only weights, aggregation statements, full citations, provenance badge. Where a biome has no quality empirical web, either curate a composite (labeled) or leave "Coming soon" — never fabricate.
4. **Per-web layout curation:** run deterministic layout, then hand-tune layout hints where crossings/labels suffer; record manual overrides in the web JSON (this is expected content work).
5. **Ecosystem index metadata** lives in `data/webs/index.json` (generated by the pipeline from individual web files — single source of truth).

## Acceptance criteria
- [ ] Full journey works: landing → biome → web → focus → cascade → back, with correct breadcrumbs and browser-back behavior.
- [ ] ≥ 4 ecosystems total (incl. Prince William Sound), spanning ≥ 3 biomes, all passing validation.
- [ ] Every new web has citations and correct provenance badges; qualitative edges flagged in legend.
- [ ] Landing page renders in < 1s; web JSONs load on demand (not bundled upfront).
- [ ] No web exceeds 25 nodes; labels legible at default zoom on all webs.

## Checkpoint Report
Standard format + landing page screenshot + a table of all webs (name, biome, nodes, edges, % qualitative edges, source). Flag biomes where data was too thin and the decision taken (composite vs. coming-soon).
